# 低维 LeJEPA：安全准备一份独立的 A4 复现目录

本入口用于将来获得训练授权后的复现。**本次仓库整理没有运行准备器，没有启动训练、特征提取或评分，也没有修改原实验结果。**

当前最小入口只覆盖 A4 的八个编码器、八个监督读出及独立状态恢复审计。它不包含后续慢因素 TEST 评分，也不声称一条命令复现全部 A1–A4、B1–B3。已有科学结果直接查看[进展同步](PROGRESS_SYNC_JEPA.md)及原封存证据。

## 1. 为什么必须另建目录

原脚本把配置、源文件和相对路径一起锁定；直接在原 `reports/` 上重跑会与已有输出冲突，修改旧脚本或回执来迁就新路径则会破坏证据。因此使用新入口 [prepare_a4.py](../scripts/low_dim_ar1/prepare_a4.py)，把已核验输入复制到仓库外的全新目录，并保留内部的 `reports/`、`work/` 布局。

准备器只使用 Python 标准库，先核验全部输入 SHA256，再通过 `copy2` 复制并核验副本。它拒绝已存在的目标目录、符号链接目标及本仓库内部的目标。它不会导入研究模块、安装依赖、启动进程或运行模型。

## 2. 准备命令与运行范围

需要 Python 3.11 或更新版本。在当前仓库根目录执行以下命令只准备文件；`/absolute/path/lejepa-a4-replay-01` 应替换成仓库外尚不存在的路径：

```bash
python3.11 scripts/low_dim_ar1/prepare_a4.py --destination /absolute/path/lejepa-a4-replay-01
```

准备完成会生成 `PREPARED.json`，其中保存源回执指纹和逐文件哈希。**`PREPARED_ONLY_NOT_EXECUTED` 只说明输入复制完整，不表示运行成功或科学结论通过。** 如果中途复制失败，准备器保留已有副本，不自动删除；检查失败原因后选择另一个新目录。

只有后续明确允许启动新训练时，才使用准备器打印的命令。在该复制目录中为 Python 3.11+ 安装 NumPy、PyTorch，并用对应解释器执行：

```bash
cd /absolute/path/lejepa-a4-replay-01
python3.11 reports/lejepa_a4_20261115/panel/run.py > reports/lejepa_a4_20261115/panel/run.log 2>&1
```

这条命令会在新目录从头训练四个原定种子 `20151–20154`、两种训练条件的编码器与读出，并执行状态恢复审计。它没有“只做检查”的含义。原代码固定使用 CPU，并限制为两线程；不能仅换解释器或添加 CUDA 环境就称为同设置的 GPU 运行。

新产物位于新目录的 `reports/lejepa_a4_20261115/panel/`：`runs/` 保存新权重及逐模型记录，`DESIGN_LOCK.json`、`RECEIPT.json` 保存新运行的来源和输出指纹，`run.log` 保存终端输出。这些文件绝不能拷回并覆盖本仓库的同名正式证据。

若要复现后续 A4 慢集比较或 A3/B 阶段，必须另外核清其校准、参考、预测封存与真值评分依赖，再准备独立工作目录。本入口没有复制那些阶段的脚本或产物，不应在这里直接接续它们。

## 3. 准备器复制什么

唯一权威清单是原 [A4 panel 回执](../reports/lejepa_a4_20261115/panel/RECEIPT.json) 的 `sources`，共13个文件。准备器固定核对该回执 SHA256：

```text
6a19ccf92e28ca1dd9dee1a05b18e9ea572adc0d0d1bddb52e2255c7522a50c8
```

下表的路径保持为该回执中的原相对路径；完整逐文件指纹写入准备目录的 `PREPARED.json`。

| 输入组 | 文件 | 在新运行中的作用 |
|---|---|---|
| A4 面板入口 | `reports/lejepa_a4_20261115/panel/run.py`、`protocol.json`、`PROTOCOL.md` | 新训练调度、原种子和状态审计预算 |
| 编码器训练依赖 | `reports/lejepa_slow_rank_20261112/training/run.py`、`protocol.json`、`runs/results.json` | 原观测变换、DGP、训练函数、超参数及源哈希核验 |
| 读出依赖 | `reports/lejepa_mechanisms_20261113/readout/run.py`、`protocol.json`、`runs/results.json` | 原读出结构、训练与验证选择函数、预算及源哈希核验 |
| 作者实现与来源 | `work/hcf_stable_id_20261027/v1/LEJEPA_SOURCE_LOCK.json`，以及其 `vendor/lejepa_identifiability/experiments/lejepa_id/` 下的 `__init__.py`、`losses.py`、`models.py` | 已锁定的 SIGReg、alignment loss、编码器构造与来源 |

两个旧 `runs/results.json` 只是原代码要求的依赖核验材料，**不是用于继续训练的状态**。准备器不复制旧编码器权重、读出权重、优化器、随机数状态，也不复制 A4 自己的 `runs/`、`RECEIPT.json`、`DESIGN_LOCK.json` 或预测结果。

已静态检查 `train_panel()` 的导入链：面板导入原编码器训练模块和原读出模块，后者复用前者的函数；作者 `models.py`、`losses.py` 只依赖 NumPy/PyTorch。13项已经覆盖这一入口的仓库内文件依赖，未发现必须额外复制的导入文件。代码中的 `FROZEN_LOADER` 只是该入口未使用的路径常量，不为它额外复制旧实验树。这里的“覆盖”来自静态检查，尚未执行新目录中的导入或训练验证。

## 4. 原种子复现与独立验证必须区分

默认配置复用原来四个训练种子、数据角色和预算，属于**按原设置重新运行**。它不会使用旧 checkpoint，但也不构成新的独立训练种子或新的统计重复。更换工作目录名称同样不增加独立性。

若目标是独立新模型验证，先在新目录中另定训练种子和数据随机流、固定假设与验收标准，再记录为新协议；不能修改本仓库的原封存配置，也不能在看过结果后不断换种子。改变窗口、动力学、标签预算、优化器或读出结构属于新比较条件，不能称为原实验的精确复现。

原依赖结果记录的环境并不完全相同：编码器旧结果记录 `arm64 / torch 2.14.0 / numpy 2.5.3`；读出旧结果记录 `arm64 / torch 2.15.0 / numpy 2.5.4`。A4 面板回执没有单独保存完整环境锁，不能把其中一份旧环境当作 A4 已核验的唯一环境。准备器不安装或强行推断这些版本，也不承诺跨平台、跨版本的数值逐位一致。实际复现应保留新环境记录，并把配置一致与数值一致分开报告。

## 5. 失败时的最小处理

- 输入哈希不一致或缺文件：停止准备，恢复正确的封存输入或报告缺失；不要重写回执中的预期哈希。
- 目标目录已存在：选择另一个全新目录，不删除旧结果腾位置。
- 缺 NumPy/PyTorch 或版本接口不兼容：在新目录对应环境处理依赖，不能直接改原封存源代码后仍声称执行了原版本。
- 新运行出现数值失败或恢复审计不足：保留日志和全部产物；不自动重启、追加种子或放宽标准。

本入口的工程状态是“代码已实现并完成静态依赖审阅”，不是“复制目录的完整训练已经通过”。
